## 简介
本文件系统化阐述浏览器窗格管理系统的设计与实现，重点围绕 BrowserPaneManager 的架构与行为，覆盖多窗格窗口协调、窗格间通信协议、动态创建/销毁流程、生命周期管理、复杂浏览器集成场景（标签页管理、历史记录同步、书签共享）、配置选项与性能优化、以及与主窗口管理器的交互模式与多工作区扩展性。

**更新** 新增远程浏览器工具桥接功能，支持远端工作空间中的代理直接驱动本地桌面浏览器实例，提供安全的跨进程通信机制。

## 项目结构
该系统采用主进程-渲染进程分层架构，现已扩展支持远程代理桥接：
- 主进程负责浏览器实例生命周期、会话绑定、网络与下载日志、截图与无障碍快照、主题色提取与观察、弹窗管理等
- 渲染进程通过 Jotai 原子同步主进程状态，浏览器工具栏以 React 组件形式与主进程通过专用 IPC 通道通信
- 窗口管理器负责应用级主窗口的创建、聚焦、关闭与广播事件
- 远程代理通过 WebSocket 能力系统与本地客户端通信，实现安全的跨进程浏览器控制

## 核心组件
- BrowserPaneManager：主进程核心类，负责每个浏览器实例的创建、销毁、状态同步、会话绑定、截图、等待、键盘输入、下载、安全挑战检测、代理 overlay 等
- BrowserCDP：基于 Electron Debugger API 的 CDP 封装，提供无障碍快照、元素几何、临时 overlay、坐标点击/拖拽、剪贴板读写等
- WindowManager：应用级主窗口管理，负责窗口创建、聚焦、关闭、RPC 事件推送、工作区关联
- browser 处理器：注册 RPC 通道，桥接渲染进程与 BrowserPaneManager
- 浏览器工具栏（React）：渲染 UI 并通过专用 IPC 通道与主进程交互
- 浏览器原子（Jotai）：渲染进程侧状态同步与派发
- **RemoteBrowserPaneManager**：远程代理桥接管理器，实现 IBrowserPaneManager 接口，负责将远程调用转发到本地浏览器实例
- **client:browser:invoke 能力**：WebSocket 能力协议，定义远程代理与本地客户端之间的通信规范

## 远程浏览器工具桥接

### RemoteBrowserPaneManager 设计与实现
RemoteBrowserPaneManager 是一个轻量级的远程代理桥接管理器，实现了 IBrowserPaneManager 接口，为单个远程会话提供浏览器窗格管理能力。它通过 WebSocket 能力系统将远程调用转发到本地桌面客户端的 BrowserPaneManager。

- **会话绑定**
  - 每个 RemoteBrowserPaneManager 实例对应一个特定的 sessionId 和 workspaceId
  - 通过依赖注入获取 rpcServer 和 getHostClient 函数
  - 实现 IBrowserPaneManager 接口的所有方法，但通过网络调用转发

- **调用转发机制**
  - invoke 方法包装 IBrowserPaneManager 调用为 BrowserCapabilityRequest
  - 通过 requestClientBrowserInvoke 发送到本地客户端
  - 支持同步和异步方法的不同处理策略
  - invokeSync 方法用于不需要立即结果的调用

- **错误处理**
  - 当没有合适的本地客户端时抛出 BROWSER_NO_CAPABLE_CLIENT 错误
  - 当客户端不支持 client:browser:invoke 能力时抛出 CAPABILITY_UNAVAILABLE 错误
  - 保留原始错误码以便远程代理正确处理

- **方法实现策略**
  - 同步方法（如 setAgentControl）通过 invokeSync 实现，避免阻塞
  - 异步方法（如 navigate、screenshot）直接 await 远程调用结果
  - 对于不支持的方法（如 uploadFile）抛出明确的错误信息
  - evaluate 方法受 allowRemoteEvaluate 配置限制

### client:browser:invoke 能力协议
client:browser:invoke 是一个新的 WebSocket 能力，允许远程代理服务器调用本地桌面客户端的浏览器工具。该能力遵循统一的协议规范：

- **能力声明**
  - 在客户端握手时声明支持 client:browser:invoke 能力
  - 服务器端通过 hasClientCapability 检查客户端支持情况
  - 支持动态发现和路由到具有该能力的客户端

- **请求格式**
  - BrowserCapabilityRequest 包含版本号、方法名、参数数组、sessionId、workspaceId
  - 版本号用于向后兼容性检查
  - 参数数组按 IBrowserPaneManager 方法签名顺序传递

- **响应处理**
  - 本地 IPC 调度器执行方法并返回结果
  - 错误通过 CodedError 保持 .code 属性
  - 支持 Buffer 和 Uint8Array 的序列化转换

### owner-key 命名空间安全机制
为防止远程会话与本地会话发生冲突，系统实现了 owner-key 命名空间隔离机制：

- **命名空间格式**
  - 远程会话使用 "remote:{workspaceId}:{sessionId}" 格式
  - 本地会话使用原始 sessionId 格式
  - 通过 toOwnerKey 方法生成 owner-key

- **实例所有权验证**
  - requireOwnedInstance 方法检查实例是否属于调用者
  - 支持 boundSessionId 和 ownerSessionId 两种所有权类型
  - 拒绝访问不属于当前会话的实例

## 故障排查指南
- 截图失败
  - 现象：捕获为空或"当前显示表面不可用"
  - 处理：先聚焦窗口，再重试；若仍失败，检查 overlay 是否被代理 overlay 挡住
- 工具栏加载失败
  - 现象：工具栏 UI 不可用
  - 处理：查看日志中的错误原因；确认开发服务器可用或打包资源存在
- 弹窗无法关闭
  - 现象：父窗口关闭后弹窗仍存在
  - 处理：确认父实例映射与弹窗集合；检查关闭事件是否正确清理
- 深链无法打开
  - 现象：深链被拦截或外部打开
  - 处理：确认 WindowManager 可用；检查 handleDeepLink 结果与回退逻辑
- **远程调用失败**
  - 现象：远程代理无法控制本地浏览器
  - 处理：检查客户端是否支持 client:browser:invoke 能力；确认会话绑定正确；验证 allowRemoteEvaluate 设置
- **权限拒绝**
  - 现象：某些浏览器方法调用被拒绝
  - 处理：检查 evaluate 方法的 allowRemoteEvaluate 配置；确认实例所有权验证；查看具体的错误码

## 结论
BrowserPaneManager 通过"原生窗口 + 多 BrowserView 分层 + 共享会话 + CDP 自动化"的架构，在保证隔离性的同时实现了高效的浏览器窗格管理。其会话绑定与复用策略、完善的生命周期与弹窗管理、强大的截图与注释能力、以及与主窗口管理器和渲染进程的协同，使其能够胜任复杂的浏览器集成场景，并具备良好的扩展性与稳定性。

**更新** 新增的远程浏览器工具桥接功能进一步增强了系统的实用性，通过安全的跨进程通信机制，使远端工作空间中的代理能够直接控制本地桌面浏览器实例。owner-key 命名空间隔离和 per-method 授权控制确保了系统的安全性，而 allowRemoteEvaluate 配置提供了灵活的安全策略。这一扩展使 Craft Agents 能够支持更广泛的部署场景，从简单的本地使用到复杂的分布式代理架构。
